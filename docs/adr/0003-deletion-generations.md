# 0003 — Confirmed deletion generations

Accepted2026-11-18. Extends ADR0002 without a new service or package.

An early reset notification stops work but cannot prove erasure. The local non-secret reset record now has a unique id and active/deleting/failed/deleted phase. In the short storage lock, the actor merges and retains the bounded outbox under the new id before making DELETE. Peers pause and keep their records during deleting/failed; a reload of an incomplete phase offers explicit recovery. Only a real204 plus successful local record removal is represented as fully deleted. A200 is not a DELETE acknowledgement. Local removal denial after server204 is reported separately. The tiny coordination marker contains no reading data, session credential or server session id and remains to reject stale work.

The shared network/session lock still waits for pending Set-Cookie issuance before DELETE expires the cookie. Every lifecycle uses a fresh generation; starting new reading cannot return to an old marker id. A local-write gate reads the current marker synchronously BEFORE touching the reading cache, protecting against a frozen tab whose BroadcastChannel/storage/visibility notifications arrive late. This closes a reproduced pagehide case that recreated an erased story anchor in a fresh session's cache. API epoch/ownership and idempotency guards remain unchanged.

Failed deletion preserves cache and outbox and pauses recording, including implicit anchor callbacks. The user may retry deletion, or explicitly continue the existing record. Continuing first performs authenticated GET me and requires the exact prior epoch; it never creates another session or imports an old queue into a new epoch. After verification, a fresh active marker resumes that same bounded queue and preserves the session's original expiry. Peer tabs must refresh their old views. A damaged sync document also falls back to a valid cache's epoch instead of losing the migration guard.

Broadcast/storage are coordination hints, not authorization. A notification causes the store to inspect its reset phase/current owned state; only the API authorizes mutations. Reader preferences, bookmarks and anchor writes are paused together. Storage failure is reported honestly rather than claiming local records were cleared. No automatic retry of destructive erasure occurs.

Evidence: actual two-tab failed DELETE/retry, retained queued choice, delayed-notification stale-tab pagehide, explicit cancellation with real database writes, and the existing late-cookie barrier. Unit fault ports separately cover invalid204/200 semantics, denied local removal, legacy markers, reload, same-epoch resume and corrupted cache cohort protection. No new feedback-day policy is selected by this decision.
