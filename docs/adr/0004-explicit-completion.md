# 0004 — Explicit completion and foreground anchor ordering

Accepted2026-11-18. Application composition only; public package/API boundaries remain unchanged.

A final completion panel owns the explicit action and next-story card. Reaching the last paragraph performs an ordinary completed=false progress write. Only the user's completion button creates completed=true at the canonical last scene/beat. The UI distinguishes local/in-memory intent from an acknowledged server record and preserves keyboard focus with an inert aria-disabled state after submission.

A pending completion is pinned as the sole progress request for its story until acknowledgement. Ordinary movement cannot replace that milestone. Its newer position remains in the already approved bounded anchor cache (or the bounded two-story memory fallback). After the completion acknowledgement, the newest matching-content anchor is submitted as an ordinary write; PostgreSQL's completed OR/furthest greatest preserve the milestone. There is no second hidden queued progress body and no new capacity policy.

Local cache entries include a non-secret document owner per story, bounded to the two story anchors. A hidden tab may flush its own final anchor but cannot replace a newer foreground owner's position. Progress intent metadata carries that owner only for ordering; it is never sent in the API body or treated as authorization. Obsolete ordinary intents are discarded before transmission while explicit completion stays pinned.

Delayed409 for an already superseded operation refreshes the revision and proceeds with the current desired operation. Current operations still have at most one CAS retry. Retry deadlines are absolute within the store, so fresh inputs/manual flush cannot bypass an existing Retry-After/backoff deadline. Uncertain retries still use their frozen operation id/body.

Final regression also exposed a real navigation race: the native local preference changed immediately, but the Web Locks callback that persisted its outbox could be lost with the old document. A single synchronous preference-intent descriptor now records the immutable original body and logical intent id before navigation. It is bounded, separate from anchor cache writers, and recovered into the existing single preference slot. A separate single binding pins a pre-cookie intent to its first authenticated epoch before mutation. Neither record authorizes a request. Settled timestamps suppress acknowledged descriptors; CAS retries keep their logical intent but receive a new operation id/body. Reload/external cache reads preserve an unsettled in-scope choice over an older server response. Confirmed erasure removes both records; failed deletion retains them. This adds no user quota or cross-device behavior.

The asset catalog projects only public rendering props into React client payloads, omitting generation provenance/raw paths. About/settings describe actual anonymous-browser storage, absolute session access expiry, asynchronous expiry cleanup, cookie-loss limitations and current verification status. Feedback day policy remains undecided and the feedback feature/task is not marked complete.
